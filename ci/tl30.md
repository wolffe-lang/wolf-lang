**wolf-lang's two.** (1) s246, 39213105199: `libc::SI_USER` and
`SI_QUEUE` do not exist for apple targets, so `wolf_rt` did not compile on

`cargo test` on macOS. The native gauntlet's `gates` shard (the aarch64
corpus, the ABI check, dist-smoke) and its `coverage` shard went red only
on (1), which a build alone catches.

**The rule** (the contract's): the merge keeps the macOS jobs that caught
a red no Linux job caught; the rest become one macOS smoke (a build and
the suite that is macOS-shaped: the terminal, signals, the directory
service) at the merge, and run in full in the nightly, whose red opens a
`nightly-red` issue. So, per repository:

- **wolf-lang**: `build + test (macos-latest)` stays (it is the smoke: the
  workspace built for aarch64-apple-darwin and every crate's tests, the
  signal and terminal lanes among them, and it caught both of s246's); the
  native gauntlet's three shards (49 macOS-minutes and three slots a run)
  leave the merge for the nightly and the release tier (§4).
- **wolf-std**: no macOS job caught one: `gates (macos-latest)` (the doc
  examples compiled and run on macOS) is the smoke, the macOS `rig`
  (std-test, 33 minutes) the nightly's.
- **pelt**: macOS's native leg stays (sh18); its release leg is the
  nightly's.
- **lobo, boreutils**: unchanged; their macOS gauntlets caught a defect.
- **yew**: the oracle on macOS stays (the restore cases); the port's macOS
  leg (the wolf tests and fuzzers, natively) is the nightly's; yew gets the
  nightly and its issue, and cancel-in-progress for pull requests.
- **wolf-book**: the rig's tests on macOS are the smoke; the macOS samples
  are the nightly's (and a toolchain release's).
- **wolf-lsp**: the server-free gate on macOS is the smoke; the server lane
  and the three editor lanes on macOS are the nightly's (four slots of a
  minute or two each).
- **wolf-interp, pax, lope, aspen**: already one smoke each; unchanged.
  **homebrew-wolf**: the release lanes' tap, no merge gate of a lane;
  unchanged.

**R-tl30-1 (asked; recommended and implemented): the trunk push runs the
merge's tier, not every job.** Each merge runs `tier full` twice, the
label's run and the trunk push's; tl29 kept every pax leg on the trunk
push (`tier all`) and moved wolf-interp's macOS in full to the nightly
alone. The macOS cap is about slots, and a trunk push is a merge's second
macOS bill: with it on `release`, a merge pays 49 macOS-minutes and three
slots once instead of never. Recommended: the trunk push is `tier full`
here and in the four tl28 repositories, as on wolf-interp; the nightly
carries the rest within a day and opens an issue on red. (The other way is
one line in `plan()`: `push` → `release`.)

**R-tl30-2 (asked; recommended and implemented): a wolf-lang release lane
runs `tier release` at the head it tags**, through the `release-matrix`
label, as wolf-interp's does since is78: the native macOS gauntlet then
runs on the exact sha a release names. `lane-audit.sh` already enforces it
once wolf-lang's ci.yml names the label (no audit change); the next
release contract (r40) gains wolf-interp's sentence for wolf-lang too. The
label exists on wolf-lang only once someone creates it: the orchestrator,
at the merge (`gh label create release-matrix -R wolffe-lang/wolf-lang`,
wolf-interp's description), or this lane on the word.
