Design and prediction:
- Keep the first five MapHdr words and dense insertion-ordered entries.
  Append only index pointer and slot count. No codegen, spec, dependency,
  or entry-point signature changes. wolf_rt_none includes the same file.
- Deterministic FNV-1a over exactly the equality bytes, followed by a
  deterministic integer avalanche. Strings hash their contents, not
  pointer/length representation. Linear probing stores entry index + 1;
  zero means vacant. Power-of-two table, at most half full. Probe loops
  are bounded even for a synthetically full table.
- On growth, allocate/zero the index in the birth region and rebuild it.
  Remove shifts entries and rebuilds in the retained table; clear zeros
  slots and keeps both buffers; copy allocates an independent index in
  the ambient region. Neither remove nor clear allocates or charges.
- Extra header charge: 16 B. Current index: 8 B per slot, 16–32 B per
  live entry beyond the initial small table. Abandoned geometric tables
  stay charged: less than 64 B per peak entry (plus the small-table
  constant); growth remains linear. Expected native ledger deltas for
  10k/100k/236k: 524176 / 4194192 / 8388496 B. Exact new index ledgers:
  1630496 / 13685536 / 28523296 B. Checked ledgers do not change.
- Normal indexed inserts/lookups become approximately linear; the dense
  order and all semantic outputs stay identical. Existing memory bars,
  corpus rows, differ, checked observations and lupin agreement stay.
- The pinned std get walks pairs(); its lookup half remains quadratic.
  Record issue mode without claiming it has become linear. The std
  change belongs to its own follow-on; do not change the pin here.

Gate bounds (R-s280-1 recommendation, implemented by the new rows):
- Native string index inserts + lookups: median time(100k)/time(50k)
  <= 2.5, three interleaved pairs. Base measured about 4.73.
- Native 100k and 236k string index workload: <= 20 times same-run C,
  three interleaved samples per size. The compiler/runtime profile and
  host are stated in every report. Base is over 1000x at both sizes.
- Also count equality comparisons in runtime unit tests to guard the
  algorithm without wall-clock noise. Functional invariants already
  true at the base are not falsely called regressions: their new
  indexed-cost assertions go red first, and the final one-hunk plant
  must break indexed removal by name.
