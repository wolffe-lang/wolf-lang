## A dial with a budget

`net_connect` waits as long as the host's own connect does, about two
minutes on Linux for an address that drops its handshake. A client that
must give up sooner can now say how long it will wait.

`net_connect_within(addr, within_ms)` answers the stream's handle as
`net_connect` does, or `timeout` once `within_ms` milliseconds are spent
(`[os.net.connect.within]` in [the OS chapter](../../spec/11-os.md)). One
budget covers every address the name resolves to, tried in turn, each
attempt given what is left of it. A budget of zero or less is `invalid`.
Name resolution happens first and is not inside the budget; a bounded
resolver is still to come
([issue 831](https://github.com/wolffe-lang/wolf-lang/issues/831)).
`net_connect` is unchanged. The call is served where `net_connect` is;
on the checked machine the dial waits beside other tasks, as
`net_connect`'s does.

## A subreaper, and the orphans it adopts

A service manager marks itself a child subreaper so that a daemon which
forks and exits leaves its child to the manager rather than to process 1.
The manager must then reap those adopted children without touching the
children it started itself.

`os_subreaper_set(on)` sets or clears the mark and answers the previous
value, and `os_subreaper()` reads it (`[os.proc.subreaper]`).
`os_wait_adopted_poll()` never waits: it answers `(pid, status)` for one
ended child that the process table does not hold, reaped, and `(0, 0)`
when none has ended (`[os.proc.poll.adopted]`). It never touches a child
the table holds, whatever order the host reports the children in; those
stay `os_wait_poll`'s. A program that keeps its own `waitid` beside the
poll can lose an end to the other reaper, so switch whole. These calls
are Linux only: macOS and Windows answer `unsupported` by name. PAX's
kernel has no subreaper attribute yet, so setting or reading the mark
answers `unsupported` there. Setting the mark on
the checked machine marks the `wolf` process it runs in.

## Answers that changed

Some of these refuse a program that 0.2.40 compiled. Each such program
read freed memory, wrote to a copy its caller never saw, or trapped where
it should not have.

- An error payload built inside a `region` block can no longer leave the
  block by `?` (E1010 at the `?`,
  [issue 1115](https://github.com/wolffe-lang/wolf-lang/issues/1115)). The
  callee built its error in the block's region, so on that error path the
  caller read freed bytes. A literal payload, a row of payload-free tags,
  a `?` before the block and the ok value's allocations are unaffected.
  The repair is to make the call before the block, or to handle the error
  inside it and raise one built outside.
- A closure parameter written without a mode is `read`, as a function's
  is, so assigning it is E1014
  ([issue 1076](https://github.com/wolffe-lang/wolf-lang/issues/1076)).
- A proc that dies by a kill or a contained trap now kills and waits for
  every proc it still owes before its own regions are freed
  ([issue 730](https://github.com/wolffe-lang/wolf-lang/issues/730)); a
  join returns only once its proc has exited, and forwards a cancellation
  to it ([issue 732](https://github.com/wolffe-lang/wolf-lang/issues/732)).
- A cancellation that reaches a blocked `select` runs its `timeout` arm,
  or leaves the `select` as `?` would. A `select` that can block, has no
  `timeout` arm and sits in a function with no row is E0604; where a
  declared row lacks `cancelled` it is E0602, and an inferred row gains
  `cancelled` ([issue 1143](https://github.com/wolffe-lang/wolf-lang/issues/1143)).
- A cast from a float to `u8`, `u16`, `i8` or `i16` no longer stops the
  native compiler on x86-64 with an internal error
  ([issue 1160](https://github.com/wolffe-lang/wolf-lang/issues/1160)).
  Every machine now truncates toward zero and traps `overflow` when the
  value does not fit or is a NaN.
- A program that names a runtime wait (`time_sleep_ms`, `fs_sync`,
  `net_connect` and the rest) but never starts a task no longer links the
  runtime's thread machinery
  ([issue 1171](https://github.com/wolffe-lang/wolf-lang/issues/1171)).

## The checked machine

`wolf conform-run --checked`, and so `wolf test`, agrees with native,
release and lupin on five more shapes: a fallible call in an
interpolation hole, a generic call with a call among its arguments, a type
parameter bound through `List[T]`, a call of the value a call returned
(`f(a)(b)`), and a `match` that reads a place instead of moving it. A dial
made while other tasks exist no longer stops the machine when it waits
past a listener's backlog, and a `select` timeout beside a task waiting on
host I/O fires on time: while such a wait is pending, the machine's clock
follows real time.

## Builds, the formatter and diagnostics

- **Stable function placement.** Hosted ELF and Mach-O builds order
  functions by module, qualified name and ABI symbol across codegen
  units. `--cold-function <qualified-name>` moves selected out-of-line
  functions into a region of their own; measure it on the program,
  because it can move resident memory either way. A linker selected with
  `--linker` or `WOLF_LD` must accept the ordering arguments, except one
  named `ligature`, which keeps the old placement and refuses cold
  requests by name. Program bytes differ from 0.2.40's even where
  behaviour does not. See
  [function placement](../cli.md#function-placement).
- **`wolf fmt`** keeps a one-armed `then` guard on one line even past the
  width. Code that 0.2.40 already formatted does not move.
- **Fewer cascade diagnostics.** A type list nested inside one that has
  already reported stays silent, so one mistake draws one report.
- **`wolf lsp`** keeps navigation in an imported file in the context of
  an open package that imports it, so references and rename find the
  package's uses of enum variants.
- **Freestanding:** a kernel can give each processor its own ambient
  region by defining `wolf_ambient_load` and `wolf_ambient_store`
  (`[abi.target.none.ambient.storage]`); a program that defines neither
  builds as before.

## The specification

Seven clauses now say what every machine already did, with no compiler
change: `check: pass`, identifiers pinned to Unicode 17.0.0, a literal
that never adopts a `distinct` type, an empty `PATH` component, the
exposure of `addr`, and two stated costs (a contained trap keeps one
thread; a finished proc's reason is kept for the life of the process).

Scoped binding headers, `if let x = e; cond { … }` and
`while var x = e; cond { … }`, are specified (`[gram.expr.if.head]`) and
planned for a later release. The 0.2.41 compiler does not accept them.

## Paired interpreter

lupin 0.1.63 gives the specification's answer in six places where 0.1.62
gave another with no diagnostic: a method call on a payload-less variant
written as a path; module state shared by every task, with unordered
accesses trapped as a race; a scope task allocating in its proc's region;
a call argument's declared type as a literal's context; undefined
behaviour and refusals on a proc's task ending the run; and a spawned
child inheriting standard output and standard error.

lupin does not resolve the four new names (`net_connect_within`,
`os_subreaper_set`, `os_subreaper`, `os_wait_adopted_poll`): a program
that calls one is `unsupported` there. Its spec and corpus pin is
unchanged at wolf-lang `5f1f1c94`; the corpus rows of 0.2.38 and later
reach lupin at its next pin advance.

## Standard library

The bundled std moves to wolf-std `32a1cd06`. It adds `std.bech32`
(BIP 173, with canonical byte conversion), strict raw standard base64,
`std.os.random` (the OS random source, refusing by name until the host's
source is qualified), and a fixed-work byte comparison. The crypto
modules and Bech32 compute the same answers without dividing, so neither
build tier puts a hardware divide on a key. `std.poll` now runs on
0.2.40's one wait: files, sockets and meanings in one waiter, at most 256
entries each, with real hang-up and error facts. `net.write_some` and
`unix.peer_credentials` are new.

The std does not yet wrap this release's new calls. A dial with a budget
and the subreaper calls come to `std.net` and `std.process` in a std
after this release.

## Known limits

- `os_term_pty_name`'s answer can leave its region with no diagnostic,
  and a native build then reads freed storage
  ([issue 1179](https://github.com/wolffe-lang/wolf-lang/issues/1179)).
  0.2.40 has the same defect; it is not new in this release. A fix is
  planned for the next one.
- A store through a `for` loop's binding writes the list on the compiled
  machines and a copy on lupin
  ([issue 1169](https://github.com/wolffe-lang/wolf-lang/issues/1169)).
- Three more places where the compiler skips a copy the language
  requires, so two names can end up sharing one value and a write through
  one shows through the other. All three are in 0.2.40 as well; none is
  new in this release:
  - A `for` loop whose body hands its element to
    `(mut pool).init(handle, element)`: the pool stores the element as it
    is instead of copying it in, so a later write through the pool changes
    the list being walked
    ([issue NNNN](https://github.com/wolffe-lang/wolf-lang/issues/NNNN)).
    A fix is in review for the next release.
  - `Pool`'s `init` outside loops stores the value it is given without
    copying it
    ([issue NNNN](https://github.com/wolffe-lang/wolf-lang/issues/NNNN)).
  - An index store whose right-hand side is not a place, such as
    `xs[i] = ys.first() else […]`, skips its copy
    ([issue NNNN](https://github.com/wolffe-lang/wolf-lang/issues/NNNN)).
  - The nightly's large property sweep is red on one mutation of a new
  corpus file: four cascade diagnostics where the sweep allows three
  ([issue 1178](https://github.com/wolffe-lang/wolf-lang/issues/1178)).
  It concerns diagnostics on invalid source only.
- Three runtime memory costs are measured and open: a freed large region
  buffer stays resident on glibc
  ([issue 1175](https://github.com/wolffe-lang/wolf-lang/issues/1175)), a
  zero-filled byte list of N bytes allocates N four times
  ([issue 1176](https://github.com/wolffe-lang/wolf-lang/issues/1176)),
  and an empty list allocates 46 bytes
  ([issue 1177](https://github.com/wolffe-lang/wolf-lang/issues/1177)).
- In the release tier, whether a single-use function is inlined depends
  on how codegen packs the program into clusters
  ([issue 1104](https://github.com/wolffe-lang/wolf-lang/issues/1104)).
- `wolf build` of a program the size of the editor yew runs out of memory
  on a PAX guest with 2 GiB or 4 GiB
  ([issue 1103](https://github.com/wolffe-lang/wolf-lang/issues/1103)).
- A region taken as a value (`let r = region()`) is never freed on the
  native tier; the block form is
  ([issue 1092](https://github.com/wolffe-lang/wolf-lang/issues/1092)).
- E1010's suggested `copy` does not converge
  ([issue 1093](https://github.com/wolffe-lang/wolf-lang/issues/1093)).
- A rejected `wolf build` piped into a reader that closes early exits 101
  instead of 2 ([issue 1094](https://github.com/wolffe-lang/wolf-lang/issues/1094)).
- A `for` over a struct value is declined with exit 4 and no code
  ([issue 1095](https://github.com/wolffe-lang/wolf-lang/issues/1095)).
- A compiled object embeds the working directory and the source path as
  spelled ([issue 1088](https://github.com/wolffe-lang/wolf-lang/issues/1088)).
- lupin types an unannotated `var` as `i32` when only a later use decides
  it as `int`, and traps `overflow` where the compiler does not; writing
  the type avoids it
  ([wolf-interp issue 173](https://github.com/wolffe-lang/wolf-interp/issues/173)).
- On macOS, the std's `term/pty_child` row
  ([wolf-std issue 147](https://github.com/wolffe-lang/wolf-std/issues/147)):
  a shell started on a pty slave takes it as its controlling terminal.

## Archives

There are four compiler host archives and a fifth companion runtime,
