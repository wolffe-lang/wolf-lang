## Source types and call frames in a debugger

A debug build (`wolf build -g`) now describes wolf's own types in DWARF:
structures, tuples, `str`, `List[T]` and `Map[K, V]` as their runtime
headers, payload-free and payload enums, error unions and optionals.
Aggregate bindings are spilled where a debugger can read them, and the
sizes and offsets come from the runtime's own layout. gdb on Linux
x86-64 and lldb on macOS arm64 print each type's value.

The same `-g` writes a non-allocated `.debug_frame` section, so a
debugger or profiler can unwind every instruction of every wolf
function, its return sequence included, without relying on frame
pointers. Frame pointers stay on, and there is still no runtime
unwinding: `[abi.native.nounwind]` in
[the ABI chapter](../../spec/04-abi.md) permits the debug-only section
and nothing more. A return sequence the compiler cannot prove is reported
as `CFI_GAP` and left uncovered rather than described with a guessed
rule; the corpus census at this release measures no gap on either host.
Location lists, inlined frames, dynamic-count arrays and release-tier
debug information are not part of this release; `--release` still
refuses `-g`.

## Patterns that name a variant

A bare variant nested in a payload pattern now tests its variant on every
tier. `K(Drink)` over `enum W { K(Kind) }` matches a `K` that carries
`Kind.Drink` and nothing else, as the checked machine and lupin always
read it; the native and release tiers used to bind `Drink` as a new name
and take every `K`. The same holds in either slot of a multi-field
payload, under a guard and in a row arm over a fallible value. A bare
name that spells none of the slot type's cases still binds it
([issue 1043](https://github.com/wolffe-lang/wolf-lang/issues/1043)).

A binder that spells a variant now warns **W0801** at the name. A `let`
or `var` pattern, a `for` header and an `else |…|` handler bind every
value they meet, so `let (Drink, n) = pair` binds `Drink` even with
`Kind.Drink` in scope. It still binds; the warning names the variant and
offers two fixes, another name (the one `wolf fix` applies) or the
qualified `Kind.Drink`. A variant is matched in either letter case, so a
binder named `fast` warns over `enum Mode { fast, slow }`. Parameters are
names, never patterns, and stay silent. A `select` arm whose receive
spells a variant (`Drink from ch`) is refused with **E0806**: a receive
cannot test, so the fix is another name and a test in the arm's body.
See `[gram.pat.binder]` in [the grammar](../../spec/01-grammar.md).

## Maps and the signal hub

A `Map` finds its keys through a hashed index behind the same seven entry
points: insertion order, `pairs()` order and every answer are unchanged,
and so are the checked machine and lupin. On x86-64 Linux, 100,000
string-key inserts with lookups take 0.020 s natively where they took
16.0 s; doubling the work now costs 1.97× the time, where it cost 4.71×.
The runtime's `Map` header is 88 bytes, with the index pointer and its
slot count after the nine existing words
([issues 1003](https://github.com/wolffe-lang/wolf-lang/issues/1003) and
[894](https://github.com/wolffe-lang/wolf-lang/issues/894)).

A fork no longer claims the signal hub's drain thread, or the reactor's
thread, while it is at work. The thread acted on a second look at its
state, and a release landing between its two looks let the next fork in a
back-to-back loop fork while the thread held the hub's lock; the child
then waited for ever at its first use of the hub, and the parent's reap of
it never ended. Both threads now act on their claim's own answer
([issue 1022](https://github.com/wolffe-lang/wolf-lang/issues/1022),
`[os.signal.hub]` and `[os.proc.fork]` in
[the OS chapter](../../spec/11-os.md)).

## Paired interpreter

Lupin 0.1.60 passes ordinary command-line arguments to a program
(`lupin FILE ARGS…`). **Options written after FILE are now program
arguments**: move `--json`, `--seed`, `--schedule`, `--std-root`,
`--trace-places` and `--argv-hex` before FILE on `run`. `conform-run` is
unchanged.

It mirrors part of 0.2.37's OS surface and declines the rest by name,
after checking each call's argument shapes:

| Surface | Compiler native/checked | lupin 0.1.60 |
| --- | --- | --- |
| directory-open bit 32 on the read modes, `fs_set_mode_fd` | served | served |
| terminal mode bit 24, `RAW_LF` | served | served |
| the nine directory-relative calls (`fs_open_at` and the rest) | served on Unix | shapes checked, then `unsupported` by name |
| `fs_statfs`, `os_chroot`, `os_getpriority`, `os_setpriority`, `os_signal_action_one` | served with documented host limits | shapes checked, then `unsupported` by name |

The declined calls are tracked in
[issue 315](https://github.com/wolffe-lang/wolf-interp/issues/315) and
[issue 321](https://github.com/wolffe-lang/wolf-interp/issues/321).

Lupin runs W0801 for binders and refuses the `select` arm with E0806 at
the compiler's spans. Its W0801 is a strict subset of the compiler's: it
never reports a span the compiler does not, and two compiler spans are
not reported there. One is W0801's match-arm half, a capitalized arm name
over a scrutinee with no cases (`lints/binder_capitalized.lu`), which
needs case tables. The other is a binder over a variant of an enum
declared as `type K = enum { … }`, whose variants lupin does not register
([issue 344](https://github.com/wolffe-lang/wolf-interp/issues/344)).
An `else |Drink|` handler now binds the error there, as the compiler
binds it.

Lupin's spec and corpus pin is wolf-lang `5f1f1c94`, which predates this
release's new corpus rows; they reach lupin's vendored corpus at its next
pin advance.

## Standard library

The bundled std adds the public-PKI TLS client: `std.x.crypto.rsa`
(RSASSA-PKCS1-v1_5 and RSASSA-PSS verification), `std.x.crypto.p384`
(ECDSA P-384 verification), and `std.x.tls.cert.validate_path`, which
builds a path from the leaf to a caller-supplied root set. A TLS 1.3
handshake now completes with servers whose certificates are RSA, RSA-PSS
or ECDSA P-384. The new refusals (`weak_key`, `bad_usage`,
`name_constraints`) are **breaking for exhaustive matches** over the
validation and handshake error sets. One limit is known and not fixed: a
TLS `read` reports a clean close, a fatal alert and a bare end of stream
alike, so a caller cannot detect truncation
([issue 133](https://github.com/wolffe-lang/wolf-std/issues/133)).

`std.x.crypto.curve25519` adds `verify_strict`, which checks everything
`verify` checks and also answers false when the public key or the
signature's commitment point has small order; `verify` is unchanged. `std.map.get` reads through the language's
index and returns an independent value on every machine: on the compiler
tiers a List-valued result used to alias the stored value, so mutating it
changed the map. The fixed tree holds 624 tests and 565 doc examples.

The std's own interpreter ledgers still describe lupin 0.1.58, so they
lag the paired lupin as they lagged 0.1.59. The rows that the ledger lists
as unsupported in the interpreter but that now run there, and the
`std/os/os.lu` doc examples whose mirror-lag entries no longer fire, are
tracked in
[wolf-std issue 125](https://github.com/wolffe-lang/wolf-std/issues/125).
Every compiler lane passes; only the test metadata is behind.

## Archives

There are four compiler host archives and a fifth companion runtime,
`wolf-rt-0.2.38-x86_64-unknown-linux-musl.tar.gz`. The latter is not a
musl compiler executable; that remains tracked in wolf-lang issue 887.
Take compiler objects and runtime from the same release. Release
publication verifies archive and runtime digests, and archive readback
and the release-tier checks are part of that workflow.
