# wolf 0.2.42

wolf 0.2.42 builds a very large program in about the memory 0.2.37 needed. It also gives `for`, `get`, `first`,
`last`, slices and a pool's `init` their own copies where the language says they hold one, and fixes a release-tier
bounds defect present since 0.2.0. **It changes the native ABI**, so read the first section before you move a pin.

## Read this before you bump the pin: the native ABI is `wolf-abi-3`

A list's header no longer stores its element size, and the runtime entries whose arguments changed are renamed
(`__wolf_rt_list32_*`, `__wolf_rt_par32_map`).
- **An object file or static archive compiled by 0.2.41 or earlier does not link against 0.2.42's runtime
  (`libwolf_rt.a`)**, and an object compiled by 0.2.42 does not link against an older runtime. Rebuild objects with
  the compiler whose runtime they link.
- **A project that keeps a prebuilt runtime or prebuilt objects moves both together**, in one change.
- In the wolf organisation that is three places:
  - **PAX** keeps a musl `libwolf_rt.a` and the user programs built against it;
  - **ligature** keeps a link bundle keyed to a wolf version;
  - **fenrir** keeps wolf, lupin and musl runtime artifacts, with a reference source rev.
- Source that 0.2.41 built is unaffected, apart from the refusals under "Answers that changed".
- The ABI chapter said `wolf-abi-0` while 0.2.41's compiler used `wolf-abi-2`
  ([issue 1185](https://github.com/wolffe-lang/wolf-lang/issues/1185)). It now says `wolf-abi-3`, which is what the
  compiler uses.

## Building large programs again

A very large program builds in about the memory 0.2.37 needed
([issue 1216](https://github.com/wolffe-lang/wolf-lang/issues/1216), 0.2.41's known issue, present since 0.2.38).
- Lowering now describes each type once per lowering unit, and every binding of that type shares the description.
- The cache key's hash reads the lowered code in place.
- The DWARF bytes, the lowered code and every cache key are unchanged, byte for byte.
- Measured on one Linux host with this release's own archive, one build at a time:
  - a native build of yew's editor, or of one of its large test programs, peaks at 5.7 GiB, where 0.2.41 peaked at
    12.1 to 12.3 GiB;
  - the editor's release build peaks at 4.5 GiB, where 0.2.41 peaked at 10.9 GiB.

## Answers that changed

Some of these refuse a program that 0.2.41 compiled. Each such program shared a value it did not own, or read freed
memory. The census of the organisation's programs and the corpus found none newly refused.

- **A `for` loop's binding holds its own value**
  ([issue 1169](https://github.com/wolffe-lang/wolf-lang/issues/1169)).
  - `for row in rows { row[0] = 0 }` no longer writes `rows`, on any machine.
  - A loop that only reads compiles to the same code as before. A loop that stores through its binding pays one
    deep copy an iteration.
  - To change the list in place, walk it by index.
- **`get`, `first` and `last` answer a value of their own**
  ([issue 1184](https://github.com/wolffe-lang/wolf-lang/issues/1184)), charged as `copy` is.
- **A slice copies its elements whole**
  ([issue 1191](https://github.com/wolffe-lang/wolf-lang/issues/1191)). A slice of a list of lists no longer shares
  the inner lists.
- **A pool's `init` copies a value handed to it plainly**
  ([issue 1183](https://github.com/wolffe-lang/wolf-lang/issues/1183)), and `init(h, take v)` moves it.
- **A `let` or `var` pattern's piece of a `read` parameter is lent**
  ([issue 1192](https://github.com/wolffe-lang/wolf-lang/issues/1192)), as a field read is.
  - Returning or keeping it is E1002, and writing through it is E1014.
  - The repair the diagnostic names is `copy` at the initializer.
- **A pty's name returned out of the region it was asked in is E1010**
  ([issue 1179](https://github.com/wolffe-lang/wolf-lang/issues/1179)). Keep it with `copy region { … }`.
- **The release tier no longer proves a list element's range from the wrong list**
  ([issue 1205](https://github.com/wolffe-lang/wolf-lang/issues/1205),
  [issue 1207](https://github.com/wolffe-lang/wolf-lang/issues/1207)).
  - From 0.2.0 to 0.2.41, a release build could print a stale element, skip a bounds trap, and read past a list's end.
  - `WOLF_MIDEND=0` is no longer needed as a workaround.

## New

- **`os_hostname()`** answers the kernel's node name, read on every call (`[os.hostname]`). On Windows it answers
  `unsupported`. lupin does not resolve it yet.

## Memory and start-up

- An empty list costs 32 bytes, not 48
  ([issue 1177](https://github.com/wolffe-lang/wolf-lang/issues/1177)). A `push` of a value nothing else holds stores
  it as it is.
- `repeat` makes its result once, in its own region
  ([issue 1176](https://github.com/wolffe-lang/wolf-lang/issues/1176)).
- On linux-gnu, a freed large region buffer gives its pages back
  ([issue 1175](https://github.com/wolffe-lang/wolf-lang/issues/1175)). A threshold you set yourself is left alone.
- Every Linux program with glibc starts with eleven fewer system calls and about 180 kB less resident memory.

## Builds

- On Linux, with no linker selected, every `wolf build` prints one note naming the linker it found (since 0.2.39).
  `WOLF_LD=cc` selects the system linker and prints no note.
- `cargo xtask` follows `CARGO_TARGET_DIR`.

## Paired interpreter

wolf 0.2.42 is paired with lupin 0.1.63 again, at its spec and corpus pin
`5f1f1c949582f53121e4047bc83c86f23ff72240`. The interpreter has not changed since 0.2.41's pairing.
- lupin's own options go before the program's file: `lupin run [OPTIONS] FILE.lu ARGS…`. Every word after the file
  is the program's. A `--seed=N` written after the file is handed to the program, and the run takes the default
  schedule.
- lupin answers `unsupported` for `os_hostname`, `net_connect_within`, `os_subreaper_set`, `os_subreaper` and
  `os_wait_adopted_poll`.

## Standard library

The archive bundles wolf-std `d58f9e1ce3af39b65a1502db21c7e6656b9f2b64`. Over 0.2.41's `32a1cd06` it adds std.fs's
wrappers of the released fs builtins: `fs.copy_chunk`, `fs.set_file_mode`, `fs.statfs` and `fs.FileSystem`, and held
directories with `fs.open_dir`, `fs.open_at` and `fs.open_dir_at`.

## Upgrading from 0.2.40 or earlier

0.2.41's refusals apply too:
- E1010 at a `?` that carries an error built inside a `region` block out of it;
- E0604 and E0602 at a `select` that can block with no `timeout` arm;
- E1014 at an assignment to a closure parameter.

One project met E1010 at 25 sites on its first build and repaired 69: each repair can expose its callers. Expect
more sites than the first build reports.

## Known limits

- In the release tier, a loop that copies list elements can stop the build with an internal error
  ([issue 1188](https://github.com/wolffe-lang/wolf-lang/issues/1188)). The native tier and `WOLF_MIDEND=0` build it.
- The nightly's large property sweep allows three cascade diagnostics at one wreck site after a single-token
  mutation. Two mutations give four
  ([issue 1178](https://github.com/wolffe-lang/wolf-lang/issues/1178),
  [issue 1231](https://github.com/wolffe-lang/wolf-lang/issues/1231)). This concerns diagnostics on invalid source
  only.
- Every socket call on every thread takes one mutex in the runtime's net layer, so a server's tasks are isolated
  but its socket work does not run in parallel
  ([issue 1230](https://github.com/wolffe-lang/wolf-lang/issues/1230)).
- In the release tier, a struct passed by value from a `mut` binding is copied whole at the call, even at the
  binding's last use, while one passed from a non-`mut` binding is not
  ([issue 1235](https://github.com/wolffe-lang/wolf-lang/issues/1235)).
- `net_wait` starts the runtime's compensation threads even when its descriptors are already ready and it does not
  block ([issue 836](https://github.com/wolffe-lang/wolf-lang/issues/836)).
- In the release tier, whether a single-use function is inlined depends on codegen's clusters
  ([issue 1104](https://github.com/wolffe-lang/wolf-lang/issues/1104)).
- `wolf build` of a yew-sized program runs out of memory on a PAX guest with 2 or 4 GiB
  ([issue 1103](https://github.com/wolffe-lang/wolf-lang/issues/1103)).
- A region taken as a value is never freed natively
  ([issue 1092](https://github.com/wolffe-lang/wolf-lang/issues/1092)).
- E1010's suggested `copy` does not converge
  ([issue 1093](https://github.com/wolffe-lang/wolf-lang/issues/1093)).
- A rejected `wolf build` piped into a reader that closes early exits 101
  ([issue 1094](https://github.com/wolffe-lang/wolf-lang/issues/1094)).
- A `for` over a struct value is declined with exit 4
  ([issue 1095](https://github.com/wolffe-lang/wolf-lang/issues/1095)).
- A compiled object embeds the working directory and the source path
  ([issue 1088](https://github.com/wolffe-lang/wolf-lang/issues/1088)).
- lupin types an unannotated `var` as `i32` when only a later use decides it
  ([wolf-interp issue 173](https://github.com/wolffe-lang/wolf-interp/issues/173)).
- lupin answers `unsupported` for a program that arms a signal handler with `os_signal_listen`.
- On macOS, std's `term/pty_child` row
  ([wolf-std issue 147](https://github.com/wolffe-lang/wolf-std/issues/147)).

## Archives

Four host archives and the musl runtime, as for 0.2.41. The musl runtime's `libwolf_rt.a` is the one PAX moves to
(see the first section).
