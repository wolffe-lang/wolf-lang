## Arguments and the entry ABI

`env_arg0()` returns the invocation name. `env_args_bytes()` returns all
arguments, including argv[0], without a UTF-8 conversion. The text readers
trap `argument-utf8` by argument index and recommend the byte reader when
an argument is not valid UTF-8.

The hosted entry is now `int main(int argc, char **argv, char **envp)`.
It calls `__wolf_rt_main_start(argc, argv, envp)` before the user program,
so static musl links see the same arguments as glibc links. This replaces
the entry's old `__wolf_rt_stack_start()` call. Objects from older
compilers are not an argument-correct substitute: take the object and
runtime from the same release. The contract is `[abi.target.main]` in
[the ABI specification](../../spec/04-abi.md).

## C variadics and selected tools

Hand-declared C variadic calls and exported variadic definitions work on
Linux x86-64 and the freestanding x86-64 target. `VaList`, `va_start`,
`va_arg`, `va_copy` and `va_end` provide cursor access; C's decayed list
parameter is `*VaList`. Other targets report E0826. The checked machine
and lupin refuse variadic execution by name rather than simulating it.

`--assembler PATH` overrides `WOLF_AS` for root-manifest assembly sources.
On native Linux, `--linker PATH` overrides nonempty `WOLF_LD` for a
cc-shaped linker. A selected tool's failure is final; neither option
silently falls back or replaces the release backend's LLVM path.

## Runtime and standard library

The start-up regression from 0.2.35 is repaired without dropping the
stack-overflow trap. Spawn and failed exec preserve host error numbers,
and a failed filesystem-copy write keeps the unwritten source bytes.
An `else` fallback swallowing a slicing range now explains its precedence.

The bundled std includes the sc72 filesystem/process wrappers,
in-place List helpers and `fs.read_into`. Lupin 0.1.58 mirrors the updated
outer-store copies and the actual List/str region corpus. Its distinct
List-element escape limitation remains wolf-interp#232.

## Musl artifacts

`wolf-rt-0.2.36-x86_64-unknown-linux-musl.tar.gz` is a runtime archive,
not a musl `wolf` executable. The latter remains wolf-lang#887.
The release workflow builds the runtime and hashes every release asset
twice before publication. Its release notes contain the archive and
runtime digests.

The matching link bundle is published separately in ligature as
`link-bundle-wolf-0.2.36`, asset `ld02-musl-link-bundle.tar.gz`:

- Archive SHA-256: `dd09895a13d3ea4056db73d3e974f025a732391c38044094ea6fc8ed69fb54cc`.
- Bundled runtime SHA-256: `3d6f821ae70ebb40d106f31c6a95ee46c0c3626d9bf230f43c1f0b8c7c26eb24`.

These identify the link bundle, not the separately built runtime-only
asset. The GNU/Linux compiler archives retain the glibc floor checked by
the release workflow; the static runtime is for libc-free musl linking.

The paired lupin 0.1.58 restores default signal dispositions before direct
exec, including SIGPIPE. The exec replacement/PID gate remains unchanged;
0.1.57's ignored-SIGPIPE regression is not waived.
